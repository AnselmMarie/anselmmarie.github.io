| <a id="d24"></a>D24 | 2026-10-05 | **The chat client hashes its POST body.** A POST through a Lambda Function URL behind OAC must carry `x-amz-content-sha256: <hex SHA-256 of the body>`; Lambda accepts no unsigned payload, so without it every send is a 403 at the origin. The client computes it with `crypto.subtle.digest`. The `/api/chat*` origin request policy forwards that header, `CloudFront-Viewer-Address` (D22) and `Content-Type`, and nothing else. Found while building Slice 4; the shell's default behavior already avoids POST for this reason (D108) | Proposed (Slice 4 fact, built in Slice 5) | 4, 5 |

| <a id="d26"></a>D26 | 2026-10-05 | **Slice 4's build-time calls.** (1) **Bundling:** `ChatFunction` is a `NodejsFunction` that bundles `libs/api/chat/src/index.ts` at synth (ESM, minified, ~1.2 MB) and **bundles the AWS SDK** rather than trusting the runtime's copy; `esbuild@0.28.2` became a root devDependency, because CDK can't find the copy that's only there through vite. No prebuilt directory, so `main.ts` passes no bundle dir. (2) **WAF lives in `infra/src/chat-firewall`**, not inside `site-distribution.ts`; the distribution takes its ARN. The web ACL's default action is allow, so it evaluates every request to the site but only acts on `/api/chat*`. (3) **The integration URL** isn't a CloudFormation attribute; an `AwsCustomResource` calls `GetWebACL` to read it into the `ChatWafIntegrationUrl` output. (4) **The guardrail version's description carries a hash of its config**, so any topic or filter change cuts a new version in the same deploy. (5) **D18's limits** default in `chat-config.ts` and can be overridden with cdk context (`chatMonthlyBudgetUsd`, `chatDailyBudgetUsd`, `chatIpDailyMessages`). (6) **The model ID is stated twice** (`type:infra` may not import `type:api`); a spec reads the handler's `chat-model.ts` and fails if they differ. (7) **WAF pricing** (aws.amazon.com/waf/pricing, 2026-10-05): $5 / month for the web ACL + $1 / month per rule × 2 = **$7 / month fixed**, plus $0.60 per million requests evaluated, which is all site traffic. CAPTCHA is $0.40 / 1,000 attempts; the page lists Challenge responses as billed but didn't show a per-response figure, so confirm it in the console before launch. None of this is in A6's budget, which watches Bedrock only | Proposed (built in Slice 4) | 4, 5 |
| <a id="d27"></a>D27 | 2026-10-05 | **Slice 5's build-time calls.** (1) **States are assistant bubbles, not banners**, as design.md proposes; the slice file's `chat-status.tsx` was dropped. An `error` bubble gets a "Try again" text button that resends the same question. (2) **`disabled` hides the launcher only after a reply says so**, once the drawer showing it is closed. There's no probe request on page load (it would cost a Lambda call and a WAF challenge per visit), so the live check reads "the next send answers disabled", not "the launcher disappears within the cache TTL". (3) **Every NDJSON line is validated** against a zod event schema added to `libs/shared/chat` (`parseChatStreamEvent`); an invalid line is dropped. (4) **A reply always ends**: a network failure, a non-NDJSON answer (a WAF challenge page) or a stream that stops without an ending event becomes the error bubble. (5) **The WAF SDK URL reaches the bundle as a Vite `define`** (`__PORTFOLIO_CHAT_WAF_SDK_URL__`), set by the deploy CLI from the now-optional `ChatWafIntegrationUrl` output, and only for the `chat` remote. Without it the build logs a warning and the client uses plain `fetch`. (6) **The status copy is invented** and lives in `chat-copy.const.ts` | Proposed (built in Slice 5) | 5 |
