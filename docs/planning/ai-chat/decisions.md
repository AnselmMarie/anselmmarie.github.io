| <a id="d21"></a>D21 | 2026-10-05 | **Bot protection (A1) is an AWS WAF Challenge rule, not Cloudflare Turnstile.** No Cloudflare services in this project. The rule sits in the web ACL Slice 4 already creates, scoped down to `/api/chat*` (page loads are never challenged), after the A2 rate rule. The chat client loads the WAF JavaScript integration SDK from the web ACL's application-integration URL and sends `/api/chat` through `AwsWafIntegration.fetch`, which attaches `x-aws-waf-token`. With no SDK URL configured (local dev, e2e), the client uses plain `fetch`. The Lambda does no bot verification, and there's no secret to store. WAF Challenge pricing is checked and recorded here when Slice 4 is built. Closes [Q3](./open-questions.md#q3) | **Maintainer** | 3, 4, 5 |
| <a id="d22"></a>D22 | 2026-10-05 | **Slice 3's build-time calls.** (1) **Pricing:** Haiku 4.5 on the US cross-region profile is **$1.10 / $5.50 per 1M input / output tokens**, cache write $1.375, cache read $0.11 (source: typingmind.com's Bedrock calculator, updated 2025-10-15; the AWS pricing page didn't render the row, so confirm in the console before launch). The prices sit beside `CHAT_MODEL_ID` in `libs/api/chat/src/chat-model/chat-model.ts` so they swap together. (2) **A5's global counter stores spend in micro-dollars**, not raw tokens: each reply adds input, output and cache tokens at their own rates, so $1 / day is compared in dollars. The per-IP counter counts **replies** (30 / day). (3) **Tags:** `libs/api/chat` is `type:api` + `scope:chat`; a new `type:api` row lets it depend only on `type:shared`. `pnpm-workspace.yaml` gains `libs/api/*`. (4) **Guardrail `streamProcessingMode: 'sync'`**, so a blocked reply is never streamed half-written. (5) **Visitor IP comes from `CloudFront-Viewer-Address`**, which Slice 4's origin request policy must forward. (6) **Fail closed:** an unreadable kill switch reads as disabled, an unreadable quota answers 503 | Proposed (built in Slice 3) | 3, 4 |
